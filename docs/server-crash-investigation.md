# Падение сервера: исправления и проверка

## Подтверждено по исходникам

- `SM_MuzzleFlash.FBX.meta`: включён `isReadable`. Это сохраняет CPU-копию
  меша для использования системой частиц в собранном приложении.
- `PlayerArmature.prefab`: удалён отсутствующий `RosRobotController` и его запись
  в списке компонентов. Скрипта с GUID `536ab92ce7431bc498520e9ec9b095e3` в проекте
  нет. **ThirdPersonController присутствует**, его настройки и ссылки сохранены.
  ROS-управление этим удалённым компонентом не восстановлено.
- `SimpleHttpServer`: запуск/остановка привязаны к жизненному циклу сервера Mirror;
  listener закрывается при остановке, уничтожении объекта и выходе. После ошибки
  accept цикл завершается, а не повторяет синхронно ошибку бесконечно. Старый цикл
  не использует новый listener при повторном старте. Ответ закрывается и при ошибке
  обработки. Чтение тела запроса асинхронное, чтобы медленный запрос не блокировал
  основной поток Unity. Продолжения остаются на Unity synchronization context:
  Unity API не переносится в Task.Run.

Это исправления реальных дефектов, но они **не доказывают устранение причины
нативного падения**. HTTP-компонент влияет только на сцены, где он используется.

## Не установлено без оригинальных логов

### JobTempAlloc

В C#-исходниках `Assets` не обнаружены выделения через `Allocator`, `NativeArray`,
`NativeList` или собственные jobs. Слепая замена TempJob на Persistent здесь
невозможна и не является решением. Источник может находиться в движке или пакетах;
предупреждение о времени жизни аллокации само по себе не доказывает причину crash.
Размеры временных аллокаторов и лимит в 4 кадра не увеличивались для сокрытия ошибки.

### Anton SDF

В репозитории присутствуют исходный `Anton.ttf` с совпадающим GUID, материал и
читаемый атлас. Шрифт динамический. Текст конкретной ошибки не предоставлен,
поэтому шрифт не переводился в Static: это могло бы сломать динамические имена
игроков и отсутствующие в текущем атласе символы. Нужен полный текст сообщения и стек.

## Проверка перед выкладкой

1. Открыть проект в Unity **6000.4.0f1** (версия проекта), дождаться реимпорта.
   Запустить `python3 -m unittest discover -s tests -v` для проверок исходных assets.
2. Пересобрать **сервер**, а не только WebGL: меню
   `Build → X1 → Собрать выделенный сервер (Linux x86_64)`.
   Также пересобрать клиент: состав компонентов сетевого префаба изменён.
   Не смешивать старый клиент с новым сервером.
3. Остановить старый процесс, выложить полный серверный билд, запустить:

   ```sh
   ./LinuxBuild.x86_64 -batchmode -nographics -scene Lasertag \
     -logFile ./server-diagnostic.log -diag-job-temp-memory-leak-validation
   ```

   Диагностический флаг использовать на время воспроизведения, а не как исправление.
4. Подключить несколько клиентов, пострелять, дождаться нескольких перезапусков
   раунда, отключиться и подключиться снова. Затем перезапустить сам процесс и
   повторить. Проверить отсутствие Missing Script и ошибки чтения SM_MuzzleFlash.
5. Для сцены с SimpleHttpServer проверить: валидный/некорректный JSON, обрыв HTTP
   соединения, StopServer/StartServer на том же объекте, выгрузку сцены, повторное
   занятие порта 8084. После остановки не должно быть потока одинаковых ошибок.
6. Если падение повторится, сохранить **полный** лог от запуска до crash, crash stack,
   код завершения процесса, график RSS и системный журнал. На Linux проверить
   `journalctl -k` на OOM-killer (SIGKILL/137 не равен нативному Unity crash).
   Особо нужны первые JobTempAlloc со стеком и точная ошибка Anton SDF.

В среде изменения кода Unity Editor не установлен: импорт assets, компиляция C#,
Linux-билд и длительный игровой прогон здесь не выполнены.
